# 部署指南

当前主应用是 Vite 构建的静态网页。运行需要浏览器支持 WebGL 2；服务器只需分发文件。模型、字体、纹理、Draco 解码器和配乐都随 `public/` 一起打包，运行时不依赖在线 CDN 或 AI 接口。

## 本地开发与成品服务

推荐 Node.js 24.x，仓库提供 `.nvmrc`。已有 nvm 时可运行 `nvm use`；其他安装方式同样可用。

```sh
npm ci
npm run dev
```

开发服务器绑定 `127.0.0.1:5187`。它支持热更新，但没有自动写入项目目录的媒体保存接口。

```sh
npm run build
npm run check -- --dist dist
npm start
```

成品服务绑定 `127.0.0.1:5186`，读取 `dist/`，保存媒体到 `output/web/`。关闭终端后需要重新启动。macOS 可在完成构建后双击根目录启动器；Windows、Linux 使用上述 npm 命令。

只想预览构建产物也可运行 `npm run preview`，地址以终端输出为准。Vite 官方说明 `vite preview` 用于本地预览，不作为生产服务器。参见 [Vite 静态部署](https://vite.dev/guide/static-deploy.html)。

## GitHub Pages

仓库已提供 `.github/workflows/pages.yml`。它会安装锁定依赖、构建、核对必要资产，然后发布 `dist/`。

1. Fork 本仓库，或推送到自己的公开仓库。
2. 在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 在 **Actions → 部署网页到 GitHub Pages → Run workflow** 运行，或向 `main` 推送更新。
4. 等待部署任务成功；点击任务的 `github-pages` 环境地址。部署地址以 GitHub 实际返回为准。

以本仓库命名，默认项目站点地址为 `https://Rising1234Sun.github.io/qingmingshanghetu/`。Fork 后用户名会变化；自定义域名另按 Pages 设置配置。

资源路径使用 `import.meta.env.BASE_URL`；工作流把 `configure-pages` 返回的 `base_path` 传给构建。因此部署在 `/qingmingshanghetu/` 时，模型会请求 `/qingmingshanghetu/models/bianjing.glb`，而非错误地请求站点根目录。

工作流只申请构建和部署需要的权限；无需在仓库中放入个人 Token。公开仓库可以使用 GitHub Free 的 Pages，私有仓库的可用性依套餐而定。官方说明见 [Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

## 普通静态托管

构建命令为 `npm ci && npm run build`，发布目录为 `dist`。托管平台的 Node 版本选择 24。不要将整个源码目录当成发布目录。

默认 `base: './'` 生成相对资源路径，可将整个 `dist/` 放在站点根目录或子目录，访问子目录时保留末尾 `/`。需要固定前缀时可以显式构建：

```sh
npm run build -- --base /qingmingshanghetu/
npm run check -- --dist dist --base /qingmingshanghetu/
```

部署到根目录可使用 `--base /`。发布后改变目录前缀时，需要重新构建。模型文件的文件名、大小写、`draco/` 路径必须保持一致。

### Nginx 示例

将 `dist/` 内容放入 `/var/www/bianjing/`，已有站点的配置可参考：

```nginx
server {
    listen 80;
    server_name example.com;
    root /var/www/bianjing;
    index index.html;

    include mime.types;
    types {
        application/wasm wasm;
        model/gltf-binary glb;
    }

    location / {
        try_files $uri $uri/ =404;
    }
}
```

替换域名和目录，再使用现有站点的 HTTPS 配置。此应用没有前端路由，不需要把缺失 `.glb`、`.wasm` 文件重写成 `index.html`。对二进制错误返回 HTML 会使解码器报错。

## 在线录像和文件保存

`scripts/serve.mjs` 是本机便利工具，仅绑定回环地址，`/__export` 只接受同端口本机页面的 Origin。公网只发布静态文件即可，无需把它改为监听 `0.0.0.0`。

公开静态站点调用 `saveMedia()` 时直接触发浏览器下载；图像、视频和录制日志不会上传到项目服务器。完整网页录制会先下载视频，再下载 JSON 日志，浏览器可能提示允许多个文件下载。MP4 不可用时使用 WebM；文件扩展名按实际编码选择。

## 上线检查

| 检查 | 预期结果 |
|---|---|
| 首次载入 | 进度结束，显示真实三维场景 |
| 模型和 Draco | 网络请求成功，响应为 GLB / WASM 而非 HTML |
| 字体、配乐、参考图 | 中文正常，点击声音可播放，简介中的虹桥图片可见 |
| 交互 | 五景、地图、标签、画质与时辰设置可用 |
| 导出 | 下载 PNG 或视频；公开域名不 POST `/__export` |
| 手机 | 控件没有横向溢出，可触摸观察场景 |

`npm run check` 校验运行资产、GLB 结构和文档内部链接；传入 `--dist` 还会核对构建资产及 HTML/CSS 引用。它不替代浏览器中的 WebGL 和功能检查。

## 常见问题

| 现象 | 排查方法 |
|---|---|
| 页面打开但停在加载 | 检查模型、纹理和 Draco 的响应，确认完整发布 `dist/` |
| Pages 下模型 404 | 核对仓库前缀和 `BASE_URL`，重新运行工作流 |
| 解码时出现 `Unexpected token <` | 文件路径错误，服务器返回了 HTML；不要对所有请求做首页回退 |
| 音乐没有自动播放 | 先点击声音按钮，浏览器需要用户交互授权播放 |
| `file://` 下无法载入 | 使用 HTTP 服务，不直接双击 HTML |
| 画面慢或发热 | 先切低画质、缩小窗口；4K 录制时实际帧率依设备性能变化 |
| 原卷小字模糊 | 参考图片分辨率有限，提高 WebGL 像素不会提升参考图的原始细节 |
| CI 报找不到文件 | 检查大小写、`.gitignore`，确认必要的 `public/` 文件已提交 |
| 本机 5186 被占用 | 先检查占用服务；可设置 `BIANJING_PORT=5188 npm start` 使用另一端口 |

大视频适合单独作为版本附件提供。GitHub 普通 Git 对大于 100 MiB 的文件会阻止提交，详见 [GitHub 大文件说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。本仓库因此排除视频、`.blend` 和安装包，保留可运行资产与重建脚本。
