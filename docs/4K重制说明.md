# 两分钟网页实测：4K 清晰度重制

本次针对旧竖屏视频的源头清晰度进行重录。使用同一套实际运行的 Three.js 网页模型与交互功能，未调用外部生成式服务。

## 旧版问题

- 原竖屏成片为 1080×1920、24 fps，视频平均码率约 3.245 Mbps。
- 完整网页在原竖屏版里缩为 1000×562；部分简介区域从约 620×434 像素放大，原始小字像素不足。
- 原页面及采集器在弹窗出现时对背景施加全画面模糊，使场景细节在说明段落内不可辨。

## 重制方式

- 在 1280×720 的界面布局下，把 WebGL 渲染缓冲区和界面采样同步提高到 3840×2160；操作仍由真实鼠标和按钮完成。
- 4K 原始录像约 7 分 32 秒，H.264 High，平均视频码率约 47.44 Mbps，实际编码帧率约 22.15 fps。源视频与操作日志保存在 `output/web/` 和 `docs/4K完整网页录制_原始.json`。
- 采集流请求 60 fps，实际只编码浏览器生成的画面；后期输出为固定 24 fps。原始日志中的 `requestedFps: 24` 是当时的目标成片帧率，已在后续采集代码中改名，明确区分采集请求与目标输出。未使用生成式插帧。
- 弹窗背景改为 20% 压暗，不再进行全画面模糊。原卷图片本身的细节仍受公开参考图分辨率限制。
- 4K 成片的标题和字幕按 2160×3840 直接绘制；上方保留完整网页，下方对同一时间的操作区域裁切放大。下方窗口由原版逻辑尺寸 1000×700 增大为 1024×962，减少标题装饰占用。
- 三维近景窗口多数接近原始像素大小；简介窗口允许常规裁切放大以便阅读，不声称每个局部都具有相同的空间采样密度。未对旧成片进行 4K 或 8K 直接拉伸，也未使用 AI 补造纹理。
- 主文件使用 H.264 High、CRF 13、BT.709、yuv420p；高清上传版从新 4K 成片缩小，使用 CRF 14。两者均不含音轨。

## 交付与核验

文件位于 `output/showcase/4K重制/`：

- `入画汴京_两分钟网页实测_4K竖屏_无配乐.mp4`
- `入画汴京_两分钟网页实测_1080P高清上传版_无配乐.mp4`
- `4K成片验收_*.png`：从最终 MP4 解码的原始像素画面。
- `新旧源画面清晰度对比.png`：同一首页视角、相同取样范围的源素材对比；动画时刻不同。

自动核验记录保存在 `docs/4K视频清晰度验收.json`，包括尺寸、实际码率、2880 帧、全片解码结果与 SHA-256。剪辑取材时间记录在 `docs/4K功能演示剪辑表.json`。

重新剪辑：

```sh
.venv/bin/python scripts/edit_showcase_4k.py
```

上传时请直接选择最终 MP4 原文件。平台转码后的画质需要在实际上传后另行核实，本次未操作用户的抖音或百度网盘账号，也不承诺平台会按 4K 原码率播放。
