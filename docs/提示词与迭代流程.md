# 提示词与迭代流程

这份文档按本项目真实需求演变，整理了可复制的提示词模板。它不是完整聊天记录的逐字转录，也不是对模型内部推理的记录。最终成果依赖多轮运行、观察和修正；相同提示词在不同环境、模型版本和资源条件下可能得到不同结果。

## 1. 开始前交代环境与真正目的

以下总提示适合在空项目中发给具有本地编码与浏览器操作能力的代理。若已经克隆本仓库，应要求代理先读源码，再修改，避免覆盖现有成果。

```text
我想实际测试 GPT-6 Astra 完成复杂项目的能力。请在当前目录制作一个
可以用浏览器打开的《清明上河图》三维仿真作品，并交付完整代码。

核心成果是可交互、可自由改变视角的三维网页。视频的用途是展示这个
实际运行的网页，包括画面和功能。三维建筑、人物、船只必须有空间结构。

参考北京故宫藏张择端本，聚焦汴河、编木虹桥与两岸市井。
原画未交代的背面、尺度可以合理推定，但请明确写出边界。
不要宣称未经验证的“完美还原”或“考古级复原”。

我重视画面细节、整体美感和功能完整性。请用旧木、青灰屋瓦、土色街道、
低饱和衣饰和自然光照，呈现繁忙生活。近景需要木构、船板、屋瓦、窗棂、
布幌、竹篮、陶器等可观察细节；远景也要有街巷层次。

本地设备为 Apple M4、16 GB 内存。软件和素材费用为零；不调用外部图像、
视频、音乐生成 API，不使用付费云渲染，不要求新账号。联网只用于核对
资料和获取免费依赖、开放授权素材，记录来源与许可。

请自行选择适合的免费工具。允许使用 Blender Python 建模，再导出 GLB，
用 Three.js 在网页实时渲染。页面、代码注释、文档默认使用简体中文。
先形成完整可运行的最小场景，再逐步增加细节。每一轮实际构建并打开
浏览器检查，把发现的问题修好，最后提供运行、部署与重建说明。
```

如果前面已经做过图片、离线影片或其他原型，可以补充：

```text
现在请以交互网页的真实效果为优先。先评估已有内容能否支持自由观察、
近景检查和实时性能。妨碍这些目标的部分可以重新制作，不必为了保留
先前工作而降低最终质量。请保留旧文件，新的主入口和当前版本写清楚。
```

## 2. 场景、空间与细节

```text
请先核对原画中虹桥形制、河道和舟船与建筑的关系，再生成三维场景。
虹桥应是开放的木构拱桥，交叠木梁、桥板、栏杆分别成形，不在河中央
添加桥墩，不把虹桥做成带廊屋的普通石桥。

按虹桥、船运、市井、建筑近景、城市全景分配细节预算。
近景补足梁柱、瓦垄、门扇、窗棂、招牌、棚布、器皿和货物。
建筑的背面也应合理，避免只对单个镜头有效。
人物有符合场景的衣帽、基本面部与自然比例，分别安排走路、挑担、
撑篙、摆摊。人物与地面、船、柜台之间的相对位置必须核对。

输出可重复运行的建模脚本与可编辑工程；固定随机种子，记录对象数量。
静态建筑和动态对象分别组织，动态对象保留导出标签，方便网页驱动。
先检查虹桥全景和市井近景，再扩展规模。发现人物穿桌、悬空或船体
穿岸等问题时，修正模型或运动逻辑，重新导出后复查。
```

本项目对应 `scripts/build_web_scene.py`、`geometry.py`、`scenery.py`、`people.py`。实际导出统计可在 `public/models/manifest.json`、`docs/网页重建.json` 查看。

## 3. 网页交互与画面

```text
请把场景做成有完整界面的中文网页。视觉风格与宋代长卷主题协调，
层次清楚，控件不遮挡关键三维内容，同时兼顾电脑和手机布局。

需要实现：
1. 左键环视、滚轮缩放、右键平移，键盘移动观察位置。
2. 五个景点按钮，镜头平滑切换到对应场景。
3. 虹桥、漕船、茶肆的空间标签；点击打开简介，再点“走近看看”。
4. 舆图定位、横向浏览原卷、复原依据说明。
5. 清晨、暖日、暮色；画质选择；动画、标签和线框开关。
6. 自动巡游、隐藏界面、全屏、原创配乐开关。
7. 真实加载进度，资源失败和图形上下文中断时有明确提示。

请使用真实按钮与状态，不做无响应的装饰控件。手动操作应退出自动巡游。
自由漫游和近距离观察时，控制相机运动的稳定性。
完成后实际点击每类按钮，检查标签与三维位置的对应、移动端溢出、
切换后状态是否一致，并记录尚未解决的问题。
```

对应 `src/main.js`、`src/tour.js`、`index.html`、`src/style.css`。

## 4. 动画、特效与性能

```text
请加入实时水面反射、细波、船体轻摇、人物关节动作、风动布幌、
柳枝、轻烟和飞鸟，保持自然、克制。特效不应掩盖模型细节。

在 16 GB 机器上以完整场景实际运行评估性能，不用空场景帧率代表成品。
静态几何按区域和材质合批，重复网格尽量共享或实例化；适当压缩 GLB。
对模型、纹理、阴影、水面反射与后期分别评估开销，提供可切换画质。
人物和船只动画采用时间增量计算，切换标签或时辰时不能重置出明显跳变。

展示真实 FPS、三角形和绘制调用读数；报告设备、画质、窗口尺寸与
采集方式。保留画面与性能之间的实际取舍，不虚构稳定 60 fps。
```

对应 `scripts/export_web.py`、`scripts/bake_web_ao.py`、`src/world.js`。

## 5. 从作品录制展示视频

```text
我希望视频客观展示整个网页的使用体验。请用真实运行的网页录制，
保留鼠标、按钮、标签简介、地图、时辰切换、线框、原卷对照、导出、
自动巡游与隐藏界面等操作过程。不能只拍几个三维运镜。

时长约两分钟，竖屏 9:16。完整页面要能看到，文字和操作细节也要看清。
可以在竖屏上方保留完整网页，下方裁切放大同一时刻的操作区域。
剪掉等待时间，但不要用其他渲染画面替换真实操作结果。
画面切换、字幕与音乐保持克制，突出 Astra 的实际使用测试。

保存原始录制、带时间戳的操作日志、剪辑表、无配乐版和可选配乐版。
检查全部功能的实际执行结果，哪些操作没有展示请写明。
```

## 6. 原生 4K 清晰度修订

这是本项目很关键的一轮修订：画布像素、录制像素、视频编码与竖屏排版需要一起处理。只修改最终 MP4 的尺寸不会补回原始小字细节。

```text
旧竖屏视频中的文字和模型细节模糊，请先检查源素材实际分辨率、
WebGL drawing buffer、DOM 采集尺寸、裁切放大比例和编码码率。
先定位问题，再重新录制。

目标主文件是 2160×3840、120 秒、24 fps。完整网页源画面按
3840×2160 原生采集，同时提高 WebGL 缓冲区和 DOM/字体采样尺寸。
正文、标题和字幕直接按 4K 输出尺寸绘制。
使用高质量编码，保留细节；不要把旧 1080P 成片直接放大充当重制。
避免弹窗后全画面模糊，保留场景可见性。

先完成短样片，从真正编码的视频抽帧观察文字与木构，再录制完整操作。
请求帧率和实际编码帧率分开报告；不得把请求参数当成实测结果。
最后检查 2880 帧、音轨有无、编码、码率、完整解码和文件校验值。
主交付突出 4K 文件，不再默认给我另外生成 1080P 版本。
```

当前实现见 `src/interface-recording.js` 和 `scripts/edit_showcase_4k.py`。有关源视频约 22.15 fps、4K 竖屏局部放大和网页界面缓存的边界见 [录制指南](录制与视频制作.md)。

```text
请把项目整理为适合公开发布到 GitHub 的仓库。README 突出这是
GPT-6 Astra 的实际使用体验测试，配真实截图，列出可运行功能和客观不足。
提供详细提示词、部署、实现原理、模型与音乐重建、4K 录制剪辑说明。

必须保证新目录 git clone 后可以 npm ci、构建、打开网页；模型、
字体、贴图和解码器都包含在运行资产中。核对 GitHub Pages 子路径，
公开站点上的导出使用浏览器下载。不要把本地写文件接口暴露到公网。

排除软件安装包、依赖目录、缓存、私密配置和大体积视频；记录第三方
素材与许可。GitHub Actions 应能构建校验并部署。发布后检查仓库文件、
工作流结果和线上加载，说明哪些成果留在本地以及如何重建。
```

## 怎样评估结果

| 观察项 | 可执行的检查 |
|---|---|
| 可用性 | 新目录克隆，按 README 启动；打开所有页面功能 |
| 三维真实性 | 改变观察方向、拉近桥背面、打开线框 |
| 细节 | 看瓦片、木构、人物与道具比例、船体结构 |
| 稳定性 | 多次换景与时辰，暂停动画，观察穿模和跳变 |
| 性能 | 同设备、窗口、画质比较实时读数，单独记录 4K 采集 |
| 清晰度 | 查看原始视频与成片元数据，按原始像素检查抽帧 |
| 交付完整性 | 文档能否解释源码、重建依赖与局限，部署是否实际通过 |

真实体验测试可以同时呈现好处与瑕疵。当前版本有完整可运行交互、程序建模和录制流程，也保留了人物动作规律、远景简化、空间推定与录制性能限制。版本、设备、迭代次数和实际人工反馈，都是理解结果的上下文。
