# 4K 录制与视频制作

视频用来展示实际网页功能，主成果仍是可交互的三维网站。建议先完成网页验收，再录制和剪辑。

## 选择正确的录制入口

“拍摄与导出”包含不同功能：

- **当前画面 4K PNG**：单张三维画面，长边 3840 像素。
- **60 秒自动巡游**：纯场景画布、配乐，当前为横屏 1920×1080 或竖屏 1080×1920。
- **完整网页操作**：包括页面按钮、标签、地图、弹窗与鼠标，可选 **4K 原生采集**。本次两分钟 4K 展示使用这个入口。

不要把 60 秒巡游按钮的 1080P 录制误认为完整网页的 4K 模式。完整网页模式保持浏览器内容区比例；16:9 布局才得到 3840×2160，竖向布局则按相同比例转换。

## 录制完整网页

1. `npm run build` 后 `npm start`，打开 `http://127.0.0.1:5186/`。
2. 等待模型、字体载入完成，调整到固定的横向窗口布局。
3. 在“拍摄与导出”中选择完整网页录制的 4K 选项，点击录制。
4. 实际执行环视、缩放、标签、景点、地图、时辰、线框、原卷、导出等操作。
5. 点击“结束并保存”或按 Esc，等待视频和日志保存。

保持网页前台和窗口大小不变；切走或改变尺寸会结束录制。关闭其他高负载应用有助于稳定采集。先录 5～10 秒样片，查看真实文件像素与文字细节后再录完整流程。

在本机成品服务中，录像和 JSON 位于 `output/web/`。公共静态网站通过浏览器下载，必要时允许多文件下载。当前完整网页录制不采集麦克风或其他应用，默认无声。

## 从原始素材剪成两分钟竖屏

`scripts/edit_showcase_4k.py` 保留本次使用的 22 段剪辑安排，生成 2160×3840、120 秒、24 fps、无配乐 MP4。上方是完整网页，下方裁切放大同一时刻的细节；字幕按目标像素绘制。

```sh
.venv/bin/python scripts/edit_showcase_4k.py --source /你的路径/完整网页原始录像.mp4 --preview
.venv/bin/python scripts/edit_showcase_4k.py --source /你的路径/完整网页原始录像.mp4
```

`--source` 用来指定本次原始录像。未指定时，脚本读取历史日志并在本项目 `output/web/` 中寻找对应文件，找不到会给出明确提示。仓库不附带数 GB 的历史原始录像。

**新的录制有新的时间线**：先修改脚本 `ROWS` 中的起始秒数、片段时长、字幕和裁切坐标，确保坐标位于 3840×2160 源画面以内、时长总和为 120 秒。历史剪辑表不能直接套在一段无关录像上。

预览写入 `output/showcase/4K重制/`，中间片段与版式在其 `剪辑素材/` 目录。正式导出会验证 2880 帧、全片解码，并更新清晰度验收 JSON。默认只导出 4K 主文件；确有需要时才传 `--include-1080p` 生成缩小副本。

## 本次主文件的实测记录

| 项目 | 记录 |
|---|---|
| 主文件 | `入画汴京_两分钟网页实测_4K竖屏_无配乐.mp4` |
| 分辨率 | 2160×3840 |
| 时长与帧数 | 120 秒，24 fps，2880 帧 |
| 编码 | H.264 High，yuv420p，BT.709 |
| 音轨 | 无 |
| 平均视频码率 | 约 35.3 Mbps |
| 原生网页素材 | 3840×2160，约 452 秒，实测约 22.15 fps |
| 源素材采集请求 | 60 fps；实际编码受本机性能影响 |

记录来源是 `docs/4K视频清晰度验收.json` 和 `docs/4K功能演示剪辑表.json`。公开版本把原电脑的绝对文件路径改为项目相对路径，媒体校验值不变。

24 fps 是最终时间戳重采样的输出规格，并不意味着源文件每秒都有 24 张独立新画面。完整页面在竖屏排版中缩小；部分简介局部采用常规裁切放大。模型几何、参考图片和 DOM 刷新频率也分别限制最终细节。

## 配乐和继续剪辑

网页自带 60 秒原创配乐；两分钟编曲可按 [重建指南](重建指南.md) 生成，将 WAV 与无配乐视频导入剪映等编辑器，保留独立音轨。源素材里已经展示了声音按钮的状态，即使最后选择无配乐，也不应把它写成没有音频功能。

主视频聚焦操作结果。适合覆盖的展示顺序为：页面全貌、鼠标与缩放、标签简介、五景、地图、时辰和画质、线框、原卷、复原说明、导出、音乐、巡游、隐藏界面。两分钟没有逐项展开全部键盘快捷键和系统全屏步骤。

上传平台时选实际导出的 4K 原文件，并在平台完成转码后检查。网站和 GitHub 源码不能决定第三方平台最终给观众播放的码率。
